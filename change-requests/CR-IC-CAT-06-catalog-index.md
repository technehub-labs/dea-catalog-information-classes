## 1. Executive summary

This CR brings the catalogue into the metaframework's catalog repository standard (CR-CATALOG-STRUCT-01) on the index dimension: a machine-generated `CATALOG.yaml` at the repo root, enumerating every entity, its state, its path, and cross-cutting content, regenerated by the vendored regenerator and validated by the vendored gate on every PR. Consumers (`dea-cli` and downstream tooling) read the catalogue by fetching `CATALOG.yaml` and following each entity's `path` field, without walking the tree.

## 2. Scope

### In scope

1. Vendored `scripts/regenerate_catalog.py` and `scripts/check_catalog_index.py` from `dea-metaframework` (v2.6.0), plus `catalog-index-schema/catalog-index-schema.json`. Vendored copies are preferred over the CI fetch fallback per the standard.
2. `CATALOG.yaml`, machine-generated and committed; regenerated on every content change.
3. CI Step 9: `regenerate_catalog.py --check` (staleness blocks merge) + `check_catalog_index.py --strict`.
4. Pointer additive change: top-level `id: dea:catalog-information-classes` added to `metamodel-pointer.yaml`, matching the same-generation fan-out in `dea-catalog-organizational-units` (additive per the pointer header: PR + patch bump).
5. Layout alignment: record subtrees renamed to the id-verbatim convention (`entities/v1-alpha/dea:information-class-<slug>/dea:information-class-<slug>.yaml`), which the regenerator's state inference requires for `canonical` state.
6. `contributions/` intake directory added (standard cross-cutting path; the strict gate warns on absence).

### Out of scope

1. The four-state per-entity lifecycle directories (`research/`, `candidates/`, `retired/` per subtree): the flat canonical records carry no state folders yet; they are added when the first research-stage or retired record lands.
2. Any record content change; the records moved, their content is untouched.

## 3. Why vendored

The standard's CI pattern fetches the tools from `dea-metaframework` at a pinned tag. Vendoring is the preferred alternative in the same standard: the copies are visible in the diff, reviewable, and the catalogue does not silently track an unpinned upstream. Updates to the vendored tools are deliberate PRs bumping the source tag noted here: source `dea-metaframework` v2.6.0.

## 4. Consumer contract

`CATALOG.yaml` exposes: catalog identity (id, name, version, status, metamodel version, repository, owner), counts, cross-cutting paths, and the entities list (id, type, version, state, lifecycle status, path, last modified). The `catalog.entities[].path` values use the id-verbatim layout.
